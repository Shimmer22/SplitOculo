# 第一个 Agent 启动任务文档
**身份**：Bootstrap Agent / Framework Agent  
**工作位置**：`SplitOculo` 主工程目录  
**核心使命**：不做大规模研究实现，先为后续所有 agent 建立“统一工程理解入口”和“第一批实验骨架”。

---

# 1. 你的任务目标

你不是来直接实现论文方法的。  
你的职责是：

1. 阅读当前 `SplitOculo` 工程已有内容
2. 提炼出后续 agent 可以依赖的整体框架文档
3. 建立实验文档体系和实验索引
4. 完成第一个实验 `EXP-001`
5. 为后续 agent 留下一个不需要全量读仓库也能工作的入口

一句话概括：

> 你负责把当前工程整理成“可持续实验”的状态，而不是直接做最终方法。

---

# 2. 你必须产出的文档

你必须新增或完善以下内容：

## 2.1 整体框架文档
创建：

- `docs/PROJECT_FRAMEWORK.md`

这是你最重要的产物。  
后续 agent 默认依赖它来理解工程。

### 它必须回答的问题
1. 这个工程现在到底在做什么
2. 端侧和云侧主流程是什么
3. 主要目录和关键文件各负责什么
4. 当前有哪些运行入口
5. 怎样跑通最小闭环
6. 哪些模块适合后续做实验插入
7. 哪些部分不要轻易改
8. 当前已知问题和坑点是什么
9. 对后续实验最关键的阅读路径是什么

### 它的格式要求
建议包含这些章节：

- 项目目标
- 当前研究定位
- 仓库结构总览
- 主流程说明
- 关键模块说明
- 运行方式
- 数据/依赖/模型说明
- 已有实验能力
- 已知问题与注意事项
- 后续 agent 阅读建议

### 它的质量要求
它必须做到：

- 后续 agent 读完后，不需要再全量读仓库
- 不是简单列目录
- 不是抄 README
- 能明确告诉别人：从哪里开始、怎么跑、哪里可以改、哪里先别动

# 3. 你必须完成的第一个实验：EXP-001

## 3.1 实验目的
`EXP-001` 不是论文方法实验。  
它要回答的是：

1. 当前工程是否已存在可复用的最小运行闭环
2. 当前工程的主流程、模块边界、运行入口是否足够清晰
3. 哪些脚本和模块将成为后续实验的基础
4. 当前已有结果与目标论文方向之间还差什么

## 3.2 你需要做的事
你应尽量在少量运行和局部阅读基础上完成以下工作：

1. 梳理工程目录和关键模块
2. 梳理边端—云端主流程
3. 确认至少一条“最小运行路径”
4. 确认后续 agent 最有可能修改的实验插入点
5. 明确当前工程对后续论文方向的支持与缺口

## 3.3 你不需要做的事
你不应：

- 直接实现 selector
- 大规模训练
- 大量重构目录
- 做大规模 benchmark
- 提前进入 `EXP-002` 之后的内容

---

# 4. 你的阅读策略

你可以全量阅读工程，但必须有选择地输出。  
你最终写到 `PROJECT_FRAMEWORK.md` 的内容必须是“筛选后的有效知识”，不是流水账。

建议阅读优先级：

1. 根目录说明文件
2. 运行相关脚本
3. 边端脚本
4. 云端脚本
5. 模型装配相关模块
6. 量化/传输/恢复相关模块
7. 已有实验或 benchmark 相关内容

若发现某些模块明显与当前论文方向无关，可在框架文档中标明“暂不建议后续 agent 阅读”。

---

# 5. 你输出的整体框架文档必须额外包含两个关键部分

## 5.1 “后续 agent 最小阅读路径”
你必须明确列一个小节，命名可类似：

- 后续 agent 最小阅读路径
- 推荐阅读顺序

内容要告诉后续 agent：

- 若只做 `EXP-002` 应读哪些文件
- 若只做 `EXP-003` 应读哪些文件
- 若只做评测应读哪些文件
- 若只做 selector 插入应读哪些文件

## 5.2 “实验插入点建议”
你必须明确指出：

1. 若后续要加 answer agreement 指标，最可能改哪里
2. 若后续要加 selector，最可能插入哪里
3. 若后续要加实验日志，最可能放哪里
4. 若后续要做小规模 baseline，最推荐先用哪条路径

# 6. EXP-001 的结果文档应回答什么

你在 `docs/experiments/EXP-001-bootstrap-baseline/RESULTS.md` 中必须明确写出：

1. 当前工程是否能支撑后续论文实验
2. 当前工程最大的三个优点
3. 当前工程最大的三个缺口
4. 后续最先做哪个实验最合理
5. 为什么不能一开始就做大规模实验

必须给出明确判断，不要只做描述。

# 8. 你输出内容的风格要求

你写的文档必须：

- 面向后续 agent
- 明确、可执行
- 避免空泛描述
- 避免只堆目录名
- 尽量指出“读哪里”“改哪里”“先别碰哪里”

你不需要把一切写得很长，但必须写得让别人能直接接手。

---

# 9. 你完成后，应留下的状态

当你完成任务后，理想状态应是：

1. 后续 agent 不再需要全量阅读仓库
2. 后续 agent 能通过主文档 + 框架文档 + 实验文档直接开始工作
3. 当前工程的研究主线与实验主线已被明确分离
4. 后续实验可以按编号推进，而不是随意开展

只有当以下全部成立时，你的任务才算完成：

1. `docs/PROJECT_FRAMEWORK.md` 已建立且可读
